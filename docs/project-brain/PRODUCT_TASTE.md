# 产品取向与不可接受的效果

**记录日期：**2026-09-28。这里记录用户明确表达的方向；具体画面仍以用户审片和当前 XIAO-Y 资产/风格包为准。审美目标不等于代码已做到。

| 用户要的效果 | 明确不要 | 对设计/验收的含义 |
| --- | --- | --- |
| 有节奏的自媒体讲解成片，人物、关键词、证据画面和对比内容随语义变化 | PPT 感、长时间静态卡片切换 | 分镜要检查持续变化和读完时间，不能只验图片数量或模板覆盖率。用户在 XIAO-Y 模板图基础上明确提出“不要有 PPT 的感觉”。 |
| XIAO-Y 以稳定身份讲清平台动态和创作者问题 | 机械重复的人物动作、通用白板动画 | 动作选取应匹配情绪/语义；人物造型、黑白黄视觉语言和角色气质保持一致。48 个动作是素材库，不是必须轮流播完的清单。 |
| 简洁、可信、清楚，适合长期生产 | 为架构漂亮而堆 Agent、部门、规则或审批 | 只有必要的责任边界与关卡；小错误本地修，不让 08 成为每帧排版的瓶颈。规则有生命周期，低价值规则可淘汰。 |
| 普通创作者用 GUI 完成真实生产 | 把 GUI 做成只会选择模型、看 JSON 的 API 调试后台 | 选题/导入、脚本、导演、素材、声音、时间线、QA、导出应有可理解的操作与下一步提示。GUI-only E2E 是 P0；不能靠内部 API 补完验收。 |
| AI 提速，人的修改仍有最终权 | 重新生成时悄悄抹掉人工镜头、动作、文字或时间线调整 | 人工编辑要可继续改、可比较、可撤销；后续 Override/Rebase 细节仍待决定，不能声称已实现完整保护。 |
| 成片可继续进入剪映精修 | 把剪映当成 Content OS 的双向事实来源 | 可单向导出原生草稿并报告损失；剪映后的改动不自动回灌 EDT。当前样片没有 `EXPORT` 产物，不能说已完成这条视频的剪映交接。 |
| 最终视觉判断由用户负责 | 用单个模型的审查结论替代人眼或多数投票 | 本条 MiniMax 曾给出时间戳不准的风险说明；保留模型原文，同时按真实时间线复核。H3 人工确认和 H4 发布分离。 |

角色图所呈现的 XIAO-Y：圆头与三撮头发、白衬衣/黑裤/黄色小方巾、黑色线稿，语气理性、犀利、幽默而接地气。现有 [人物注册表](../../registries/characters/XIAO-Y_V1.json)和[风格注册表](../../registries/styles/XIAO-Y_STYLE_V1.json)定义可执行的资源与颜色。当前正式视频证明一个 84.82 秒样片可被审片通过；这不能证明所有题材和更长时长已经达到同样质量。

工作流层面的取向还包括：品牌定位与创作政策优先于短期点击率，Analytics 可提出观察/假设，不能把偶发高数据直接提升为 Rule；审计独立但不能改稿。来源：[工作流宪章](../../WORKFLOW_CONSTITUTION.md)和本窗口早期 Content OS 讨论。未经用户确认的具体画面偏好应放在 [开放问题](OPEN_QUESTIONS.md)，不要补成“用户一直想要”。
