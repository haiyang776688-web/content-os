# VGB-002 · Four-way comparison

Date: 2026-09-29
Status: AGENT_REVIEW_COMPLETE / AWAITING_HUMAN_VISUAL_CHOICE

本表直接比较 VGB-001 A、VGB-001 B、VGB-002 F1、VGB-002 F2。等级不求和，不构造百分制。`PPT feeling` 表示控制 PPT 感的能力，等级越高越好；`Text overload` 表示控制文字过载的能力。

| Dimension | VGB-001 A | VGB-001 B | VGB-002 F1 | VGB-002 F2 |
| --- | --- | --- | --- | --- |
| Watchability | **WEAK**：清楚但像软件说明巡读。 | **WEAK**：reaction 有效，中段回到图解页轮播。 | **GOOD**：证据路径中加入人物节拍，仍偏专业教程。 | **GOOD**：引入、停住、reaction、人工责任、绑定与引用形成完整推进。 |
| Evidence clarity | **GOOD**：原 UI 目标清楚。 | **GOOD**：头尾证据可读，中段主要是抽象图示。 | **STRONG**：入口、规则原文、人工审查、来源与 Fact ID 都保持大幅可读。 | **STRONG**：reaction 和人物镜头都回到同一证据位置；人工审查和 Fact ID 可读。 |
| Brand identity | **WEAK**：几乎没有 XIAO-Y。 | **STRONG**：白黑黄红与角色反应最接近参考。 | **GOOD**：品牌 chrome 和有限人物成立，但强度仍低于 B。 | **STRONG**：角色承担五个明确任务，颜色、线条和近景保持 B 的品牌人格。 |
| Visual rhythm | **WEAK**：有意义的运镜仍主要是在读页面。 | **GOOD**：尺度变化明显，但完整构图频繁重置。 | **GOOD**：人物只打断关键节点，证据连续。 | **GOOD**：证据与角色形成呼吸，动作均对应语义变化；实时感受仍待用户确认。 |
| PPT feeling | **WEAK**：从幻灯片转为帮助文档导览。 | **WEAK**：候选≠Fact、人工把关、Fact Pack 是三个完整页面。 | **GOOD**：大部分内容留在 Workbench 连续空间；关系段仍有图解感。 | **GOOD**：reaction 后返回触发它的原证据，人工责任和来源绑定通过前后对象衔接；白底关系段仍保留少量 editorial-board 感。 |
| Text overload | **GOOD**：新增文字少。 | **GOOD**：短标为主。 | **GOOD**：字幕之外每镜最多一个短标；原 UI 无关字仍存在。 | **GOOD**：除“等等”外不复写旁白；关系词限制为最少短标。 |
| Visual protagonist clarity | **GOOD**：焦点明确。 | **GOOD**：分段明确，但页面之间连续性弱。 | **STRONG**：证据几乎始终是 PRIMARY，人物只做标点。 | **STRONG**：人物主导 reaction/责任时，证据退为上下文；其余时段证据接管。 |
| Screenshot readability | **GOOD**：关键 UI 放大可读。 | **GOOD**：导入区与 Fact ID 可读。 | **STRONG**：人工审查拆为两段原像素裁片，导入与 Fact ID 保持大幅。 | **STRONG**：同 F1，并在 reaction 画面保留真实规则说明。 |
| XIAO-Y usefulness | **GOOD**：克制缺席合理，但品牌弱。 | **GOOD**：引路、反应和把关有分工；部分人物镜头像贴图。 | **GOOD**：开场、反应、责任、收束都有理由；不持续占屏。 | **STRONG**：引入、reaction、责任、过渡、收束均改变视线或语气，删除任一段会损失明确功能。 |
| Continuity | **GOOD**：同一 UI 空间较连续，关系段另起。 | **WEAK**：中段多次切到独立白底构图。 | **STRONG**：UI 高亮、人物反应、人工审查、关系线、Fact ID 按因果连接。 | **STRONG**：候选 token 停在门前、reaction、返回原规则、责任镜头、来源到 Fact ID 均有前后接点。 |

## Review caveat

“更愿意继续看”最终只能由用户实际播放判断。本轮没有实时连续声画观看，不能把密集帧中的连续关系自动等同于真实观看节奏。用户若认为 F2 仍是 A/B 拼贴，则以用户判断为准并记录融合假设失败，不继续自动迭代十次。
